Данное ТЗ описывает минимально жизнеспособную версию (MVP) для лабораторной работы №1. Расширение функциональности (авторизация, веб-интерфейс, отчёты, резервное копирование) планируется в последующих лабораторных работах.

## 1. ОБЩИЕ ПОЛОЖЕНИЯ

### 1.1 Наименование системы

Полное наименование: Система управления конференциями, докладами, спикерами, участниками и оценками.

Краткое наименование: «Конф+».

### 1.2 Назначение и область применения

Система предназначена для автоматизации процессов:

- создания и ведения конференций;
- подачи и утверждения докладов спикерами и администраторами;
- регистрации участников на конференции;
- оценки докладов участниками;
- формирования отчётов по активности и качеству докладов.

Область применения – научные конференции, бизнес-мероприятия, внутренние корпоративные семинары.

## 2. ОСНОВАНИЯ ДЛЯ РАЗРАБОТКИ

Разработка ведётся в рамках учебной дисциплины «Методология и практики DevOps» по направлению 10.03.01 «Информационная безопасность».

## 3. НАЗНАЧЕНИЕ РАЗРАБОТКИ

### 3.1 Функциональное назначение

Система обеспечивает:

- регистрацию и разграничение доступа пользователей (администратор, спикер, участник);
- CRUD-операции для конференций;
- обработку заявок на доклады с проверкой правил;
- регистрацию участников;
- приём и обработку оценок докладов;
- проверку работоспособности через эндпоинт `/health`.

### 3.2 Эксплуатационное назначение

Система предназначена для использования сотрудниками организации (администраторами) и внешними пользователями (спикеры, участники) через HTTP API (например, с помощью curl или Postman).

## 4. ТРЕБОВАНИЯ К СИСТЕМЕ

### 4.1 Функциональные требования

*Таблица 2 – Описание функций*

| Функция | Описание |
|---|---|
| CRUD для конференций | Создание, изменение дат/места, просмотр списка, удаление. |
| CRUD для докладов | Подача заявки (название, аннотация, длительность), изменение до утверждения администратором, утверждение/отклонение. |
| Работа с регистрациями | Участник может зарегистрироваться на конференцию; проверка дат и дублирования. |
| Оценка докладов | Участник ставит оценку (1–5) и пишет отзыв; проверка правил (нельзя оценить свой доклад, только после завершения конференции). |
| Отчёты | Простой отчёт по количеству докладов, участников, средним оценкам (опционально). |
| Проверка работоспособности | `GET /health` возвращает `{"status":"ok"}`. |

### 4.2 Требования к надёжности

- Система должна обрабатывать ошибки пользовательского ввода с выдачей понятных сообщений.
- Данные должны сохраняться транзакционно (целостность операций).

### 4.3 Условия эксплуатации

Система работает под управлением операционной системы (Linux/Windows) и взаимодействует с СУБД PostgreSQL.

### 4.4 Требования к информационной и программной совместимости

- Взаимодействие клиент-сервер – по протоколу HTTPS, данные в формате JSON.
- СУБД – реляционная (PostgreSQL или SQLite).
- Конфигурация приложения (строка подключения к БД, порт, режим отладки) задаётся через переменные окружения, шаблон которых находится в файле `.env.example`.

## 5. ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА СИСТЕМЫ

- Длительность доклада должна быть положительным числом (больше нуля).
- Дата окончания конференции позже даты начала.
- Регистрация на конференцию возможна только до даты окончания регистрации (если не задана, то до начала конференции).
- Участник не может оценить доклад до завершения конференции.
- Спикер не может оценивать свой собственный доклад.
- Оценка должна быть в диапазоне от 1 до 5.
- При нарушении правил возвращаются HTTP-статусы (некорректные данные) или 409 (конфликт с бизнес-логикой).
